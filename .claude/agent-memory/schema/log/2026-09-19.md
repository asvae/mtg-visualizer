## `SinkInstance` callable returns `boolean`; `SinkFamily<Config>` returns `SinkInstance[]`
3rd real design iteration on the callable contract, two live corrections in
one task (relayed mid-task by the coordinator, not asked for directly):

1. `SinkInstance`'s call signature `(candidate, root?) => SinkMatchDetail |
   null` -> `(candidate, root?) => boolean` (producer question only —
   user's exact target: `const b = sinkInstance(candidate)`, rejected two
   compromises as "both complete bullshit"). `SinkMatchDetail` deleted
   entirely. `predicateDerived` moved to a new, separate, optional
   `SinkInstance.isPredicateDerived?(candidate, root?) => boolean` accessor
   — the one real piece of the old combined return `card-interactions.ts`'s
   `selfDirectProducerMatch` still needs and a bare boolean can't carry.
   Both `CountersSink`/`BattlefieldPresenceSink` implement it.
   `card-interactions.ts`'s `matchEntry` and `server/api/sink-catalog/
   index.get.ts`'s `instanceConsumerMatched` no longer route the CONSUMER
   question through the callable at all (whether callable or not) — they
   call `matchesConsumerTriggerNames`/`matchesConsumerTriggerOn`/
   `matchesBattlefieldPresenceConsumer` directly against the entry's own
   plain data fields uniformly (this also fully fixed
   `instanceConsumerMatched`'s pre-existing `matchesBattlefieldPresenceConsumer`
   omission for the non-callable branch — never actually mattered in
   practice since only callable entries carry that field, but now
   structurally correct either way).
2. `SinkFamily<Config>` return type `SinkInstance` -> `SinkInstance[]` (2nd
   live correction: "we need array handling here obviously"). `CountersSink`
   now derives one instance PER DISTINCT `counterType`
   (`deriveCounterType` singular -> `deriveCounterTypes` plural, `Set`-based
   dedup) instead of silently keeping only the first found. Dedup rule
   stated generally per explicit user framing: identical-effect duplicates
   collapse to one instance, any real difference gets its own — for
   Counters, `counterType` alone is the complete identity key since every
   other derived field is a pure function of it + the whole definition.
   `BattlefieldPresenceSink` — conforming edit only (still `SinkQuery`/
   `matchSink`-based internally), now returns `[sink]`. All 4 real instance
   files (`counters-plus1plus1.ts`,
   `battlefield-presence-{cats,creatures,hare-apparent}.ts`) now read
   `...(...)[0]!` — NOT destructuring (`const [x] = ...`), since a live
   `tsc --noUncheckedIndexedAccess` probe confirmed that infers `T |
   undefined`, and the Nuxt-generated tsconfig sets that flag even though
   `functional-model/tsconfig.json` itself doesn't.

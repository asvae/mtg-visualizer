## `CountersSink(definition: CardDefinition)` — public factory signature change
Rewrote `families/counters.ts`: `CountersSink(config: CountersSinkConfig)`
-> `CountersSink(definition: CardDefinition)`, per user's "I don't care
about magical configuration file. Sink(definition). Got it?" instruction.
`CountersSinkConfig` deleted entirely. New private helpers derive
slug/counterType/consumerTriggerNames from the passed `CardDefinition`:
`deriveCounterType` (walks `effects` + `triggers[].effects`, throws if no
real counter-granting effect found), `slugForCounterType` (deterministic
sanitization, reproduces `'counters-plus1plus1'` byte-for-byte so
`sink-catalog-status.ts`'s file-lookup-by-slug convention keeps working
with zero other-file changes), `deriveConsumerTriggerNames` (investigated
"no `Trigger.on` field" as a possible reserved discriminator — confirmed
it is NOT one anywhere in the codebase, dozens of unrelated name-only
triggers exist pool-wide; used a small family-owned name allowlist,
`['onCounterAdded']`, with an `on`-field exclusion safety net instead).
Mid-task coordinator relay: user sharpened the chain to `SinkFamily
(sinkCandidateDefinition) -> (Predicates) -> Candidate Definition` — added
a named `withPredicates(counterType, consumerTriggerNames)` step (returns
`{producer, consumer}`) so the middle step is visible code, not anonymous
closure logic; did NOT rename `definition`/`candidate` params to match the
user's diagram literally (would collide with the pre-existing, differently-
scoped "Source/Sink Candidate" UI vocabulary — flagged, not silently
picked). Second coordinator relay ("throw away complete bullshit") —
confirmed scope stayed Counters-only, used as license to delete
`CountersSinkConfig` outright rather than deprecate it.

`counters-plus1plus1.ts` now imports the real `exemplarOfLight`
`CardDefinition` and calls `CountersSink(exemplarOfLight)`.
`counters.test.ts` builds an inline mock `CardDefinition` shaped like
Exemplar of Light (not importing the real one, per this file's own
"mocks inline" convention) and calls `CountersSink(mockDefinition)`; added
5 new derivation-focused test cases (slug/category/consumerTriggerNames
correctness, a `-1/-1` differently-typed driving definition, throw-on-no-
producer-effect, both `on`-field discrimination edge cases).

Updated `entry.ts`'s `SinkFamily<Config>` doc comment,
`SINK_MODEL_DESIGN.md` (new "2c" section + open-items update),
`.claude/contracts/card-schema.md` (new section 12).

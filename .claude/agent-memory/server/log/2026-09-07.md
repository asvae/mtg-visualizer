# 2026-09-07

- Prod 500s on `/api/card/[set]/[number]` (and presumably
  `/api/cards/by-names`, `/api/tokens/by-key`) traced to Netlify build/
  functions running on a default Node version older than what
  `import { DatabaseSync } from 'node:sqlite'` needs (unflagged import
  requires Node ≥22.13/23.4; module doesn't exist at all before 22.5).
  Neither `netlify.toml` nor `package.json` had any Node version pin, so
  Netlify fell back to its own (older) default → import throws at
  function cold start → 500 on every call. Confirmed as a runtime/shell
  issue, not route logic, by checking the plain unflagged import in all
  three files matches local (Node v24.11.1) working fine.
- Fix: added `[build.environment] NODE_VERSION = "24"` to `netlify.toml`
  and `"engines": { "node": ">=22.13.0" }` to `package.json`. Committed as
  `04dd9476` ("Pin Node 24 for Netlify to fix node:sqlite 500s") — the
  `netlify.toml` change ships with a detailed inline comment explaining
  the whole issue, so this is fully documented in-code going forward.
- Resolution confirmed: a distinct, later prod-500 issue on the same route
  (`8608c574`, "Fix prod 500 on /api/card: functional-model live-trace is
  dev-only") was found and fixed afterward with no further mention of the
  `node:sqlite`/Node-version problem — the pin held.

## Sink-catalog "Real FDN pool matches" fix: shared thumbnails, drop Producer section

User complaint: `EngineConsoleCardMatchChip.vue` (a `ui`-agent-authored
component on `/app/engine/sinks/<family>`) built a LIVE per-card Scryfall
image URL client-side and fired one request per matched card — 111
simultaneous requests for `battlefield-presence`'s real producer-match
count. Deleted it outright (not salvageable — the live-fetch approach was
itself the bug). Real fix, three parts:

1. **Server-side enrichment.** Extracted
   `resolveFunctionalModelCardMeta`/`cardMetaCache` (name -> real
   set/collectorNumber/image, 3-leg resolution: FIN's own
   `fin_scryfall.json`, then `data/cards.db`, then a live paced Scryfall
   call) out of `server/api/card/[set]/[number].ts` into a new shared
   `server/utils/cardMeta.ts` — that route now imports it too (no private
   copy left to drift). Also extracted the paced `scryfallFetch` itself into
   `server/utils/scryfallFetch.ts` (shared single per-process pacer — the
   whole reason it's paced is a process-wide 10req/s ceiling, not per-file).
   `server/api/sink-catalog/index.get.ts`'s `computeRealMatches` now returns
   `SinkCatalogRealMatch[]` (`{card, image, set?, collectorNumber?, self?}`,
   `self` always `undefined` here — no single "self" card on this page, kept
   only for prop-shape parity with the reused component) instead of bare
   `string[]`, via a new `enrichMatchNames` helper; the route handler is now
   `async`.
2. **Client-side reuse, not a new component.** New
   `app/components/CardMatchGallery.vue` — pure presentational, extracted
   from `CardDetailTabs.vue`'s own FDN "Sinks" section (NuxtLink to
   `/app/card/<set>/<number>`, real `<img>` or text-fallback box, `ring-2
   ring-primary` self-outline). Both `CardDetailTabs.vue`'s Sinks section
   AND `app/pages/app/engine/sinks/[[slug]].vue`'s "Matches" section now
   import this SAME component — literal fix for "component use the one from
   Cards > Sinks, don't spawn new components." Did NOT touch the OTHER
   match-gallery block in `CardDetailTabs.vue` (the FIN `orderedInteractions`
   panel, ~line 2008) — different match shape (`selfInteraction` not
   `self`), out of scope, left alone to minimize risk.
3. **Section rename + Producer-matches removal.** Read
   `functional-model/sink-model/SINK_MODEL_DESIGN.md` first (its thesis:
   consumer-side curation is the one place real judgment concentrates).
   "Real FDN pool matches" -> "Matches"; the entire Producer-matches
   `<details>` collapsible deleted outright (not hidden/collapsed) — for
   `battlefield-presence` it was 111 cards, essentially "every creature,"
   not review-worthy. Inner consumer-section summary label simplified to
   "Who owns/reacts to this event" (dropping the now-redundant "Consumer
   matches —" prefix, since Producer is gone there's nothing left to
   disambiguate against). Added a fallback message for the rare case an
   entry declares NO consumer-side signal at all (`realMatches.consumerMatches`
   `undefined`) — the old code silently rendered nothing for that case since
   Producer was always shown regardless; now Producer is gone so this needed
   its own explicit message. Also removed the now-dead
   `/api/card-status/fdn` name->number lookup fetch from the sinks page
   (`fdnNameToNumber`) — no longer needed now that the server sends
   set/collectorNumber directly per match.

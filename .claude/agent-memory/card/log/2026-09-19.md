## Forge Compiler tab (forge-json-compiler experiment, RUN at request time)
Added "Forge Compiler" tab surfacing another (different) engine-side
experiment, `functional-model/scripts/experiments/forge-json-compiler/`
(compiles Forge's own JSON into a real `CardDefinition` + structural-diffs
it against the hand-authored one) — narrow, ONE card only (Exemplar of
Light). Unlike Forge JSON Mapper (a precomputed on-disk file this tab just
reads), this one has no precomputed output — the server actually RUNS
`compileForgeCard()` + the diff at request time. Design departs from the
Forge JSON Mapper precedent and instead followed Forge Script's: a separate
dev-gated endpoint (`GET /api/forge-json-compiler?name=`) fetched client-side
via `$fetch` (not baked into `FunctionalModelData`/`cardResponse.ts` — no
hand-mirror-gotcha exposure this time), tab visible dev-wide with its own
inline per-card "not available" state rather than hidden per-card. New:
`functional-model/scripts/experiments/forge-json-compiler/diff.ts` (lifted
`structuralDiff` out of that dir's own `run-experiment.ts` so both it and
the new server util share one implementation; `run-experiment.ts` re-verified
standalone via `npx vite-node` after the extraction, still real output),
`server/utils/forgeJsonCompiler.ts` (dev-only gated, hardcodes the
one-card-name check BEFORE ever calling the compiler — never lets an
unsupported card reach `compileForgeCard`/its `UnsupportedForgeShape`
throw), `server/api/forge-json-compiler/index.get.ts`. Edited (additive):
`useGraphStore.ts` (`FUNCTIONAL_MODEL_TABS`), `CardDetailTabs.vue` (new
